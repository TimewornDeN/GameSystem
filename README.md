# GameSystem

Проста текстова гра з консольним і графічним (WPF) інтерфейсом (.NET 10). Можна створювати персонажів, предмети й вміння,
переглядати каталог усіх персонажів із віддаленої бази (з портретами), додавати їх у гру, битися двома персонажами,
зберігати гру та результати боїв і продовжувати з останнього збереження.

Репозиторій: <https://github.com/TimewornDeN/GameSystem>. Усе описано в [дизайн-документі](docs/DESIGN.md);
розділ 13 зіставляє кожен пункт технічного завдання з тим, де він виконаний і як це перевірити.

## Встановлення (готова програма)

Готові пакети лежать на сторінці [Releases](https://github.com/TimewornDeN/GameSystem/releases) репозиторію. .NET встановлювати не потрібно: усе, що треба для запуску, вже всередині.

| Пакет | Що це | Система |
|---|---|---|
| `GameSystem-Window-<версія>-win-x64.zip` | графічне вікно (`GameSystemWindow.exe`) | Windows 10/11, 64 біти |
| `GameSystem-Console-<версія>-win-x64.zip` | консольна версія (`GameSystem.exe`) | Windows 10/11, 64 біти |

1. Завантажити потрібний zip і розпакувати в будь-яку папку.
2. Запустити `GameSystemWindow.exe` (двічі клацнути) або `GameSystem.exe` (з терміналу чи двічі клацнути).
3. Збереження й результати боїв програма сама кладе в `%LOCALAPPDATA%\GameSystem`, тому папку програми можна видалити чи перенести без втрати збережень.

Якщо Windows SmartScreen показує «Windows protected your PC», це через те, що exe не має платного цифрового підпису: «Більше інформації» → «Усе одно виконати».

## Збирання з початкового коду

Потрібне лише [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0). Більше нічого окремо ставити не треба: NuGet-пакети (xUnit для тестів) завантажуються самі при першому збиранні.

```
git clone https://github.com/TimewornDeN/GameSystem.git
cd GameSystem
dotnet test GameSystem.slnx -c Release
```

Зібрати пакети для розповсюдження (Release, self-contained, один exe-файл):

```
# Windows, PowerShell: консольна й віконна версії
.\scripts\publish.ps1

# Linux / macOS: лише консольна версія (вікно працює тільки на Windows)
./scripts/publish.sh linux-x64
```

Результат з'являється в папці `dist`: по одному zip на кожну програму. Скрипт спершу запускає всі тести і не збирає пакети, якщо хоч один тест не пройшов.
Один проєкт вручну:

```
dotnet publish GameSystem.CLI/GameSystem.CLI.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true
```

Реліз на GitHub створюється сам: достатньо поставити тег `v1.0.0` і виконати `git push --tags`. Файл `.github/workflows/release.yml` прожене тести, збере пакети й додасть zip до релізу.

## Запуск з початкового коду

```
dotnet run --project GameSystem.CLI
dotnet test
```

Далі в програмі: `help` покаже всі команди, `exit` вийде.

## Графічне вікно (Windows)

```
dotnet run --project GameSystem.Gui
```

Вікно має три вкладки:

- **Гра** працює як консоль: поле виводу, рядок вводу, список збережень із кнопками «Зберегти», «Завантажити», «Продовжити»
  і кнопки команд та дій у бою.
- **Каталог персонажів** — прокручуваний список карток усіх персонажів, яких пропонує сервер: портрет, ім'я, зірки, титул,
  стихія й зброя, короткий опис. Кнопка «Оновити каталог» завантажує список заново, кнопка «Додати в гру» на картці створює
  цього персонажа в грі. Список і портрети зберігаються на диску, тому каталог відкривається й без мережі.
- **Персонажі в грі** показує картки тих, хто вже є в грі (здоров'я, характеристики, предмет), і дозволяє додати персонажа із сервера за id.

Подробиці: [docs/DESIGN.md](docs/DESIGN.md), розділи 11 і 13.

## Швидкий приклад

```
create char          # діалог: ім'я та клас
create char
ls char              # таблиця персонажів
play                 # вибрати двох бійців і почати бій (у бою: attack, heal, defend, ability, status, surrender)
results              # історія боїв
save mygame          # зберегти стан персонажів
```

У бою доступні ще `history` (історія дій) і `save <n>` (зберегти гру посеред бою).

## Каталог персонажів

Каталог — це список усіх персонажів, яких пропонує сервер [genshin.jmp.blue](https://genshin.jmp.blue/). Він зберігається в папці
даних користувача, тому після першого завантаження відкривається без мережі.

```
catalog                  # таблиця всіх персонажів (якщо каталогу ще немає, він спершу завантажується)
catalog refresh          # завантажити каталог із сервера заново
catalog info albedo      # загальна інформація, посилання на портрет і файл портрета на диску
catalog portraits        # завантажити портрети всіх персонажів у локальні файли
remote create albedo Albi   # додати персонажа з каталогу в гру під іменем Albi
sheet Albi               # аркуш персонажа, у ньому теж є посилання на портрет
```

Портрети лежать у `%LOCALAPPDATA%\GameSystem\portraits` як `<id>.png`, їх можна відкрити будь-яким переглядачем зображень.

## Збереження й продовження гри

Збереження лежать у папці даних користувача (`%LOCALAPPDATA%\GameSystem` на Windows, `~/.local/share/GameSystem` на Linux); при старті програма
показує точний шлях. Змінна `GAMESYSTEM_HOME` змінює цю папку.

```
save evening         # зберегти гру (якщо йде бій, він теж зберігається)
list                 # список збережень
load evening         # завантажити світ
continue             # продовжити з останнього збереження, у тому числі повернутися в бій, що не закінчився
continue evening     # те саме, але з вибраного збереження
```

Подробиці й схеми: [docs/DESIGN.md](docs/DESIGN.md), розділ 10.

## Нові персонажі з файлу

Профіль персонажа лежить у папці `characters` поруч із програмою як `<name>.json` (у пакеті й при `dotnet run` ця папка вже є з прикладами). Приклади є в `samples/characters`.

```
import --list           # які профілі є
import zed               # додати персонажа Zed з його предметом і навичками
```

## Механіка бою

Шкода рахується так: від удару віднімається броня, а потім застосовується відсоток опору (мінімум 1 шкоди).
Швидкість задає порядок дій, а швидкий боєць може діяти кілька разів за крок. Баффи й дебафи діють кілька ходів.
Усі формули й схеми: [docs/DESIGN.md](docs/DESIGN.md), розділ 9.

## Проєкти

| Проєкт | Призначення |
|---|---|
| `GameSystem.Core` | правила гри, бій, каталог персонажів, текстова система, інтерфейси |
| `GameSystem.Infra` | консоль, JSON-файли (збереження, результати, каталог), HTTP-клієнт і портрети, рендер тексту |

| `GameSystem.Presentation` | логіка вікна без WPF: консоль вікна, запуск гри в окремому потоці, view-моделі, картки каталогу |
| `GameSystem.Gui` | графічне вікно на WPF (XAML, конвертери, точка збирання) |
| `scripts` | скрипти збирання пакетів (`publish.ps1`, `publish.sh`) |
| `.github/workflows` | автоматичний реліз на GitHub |
| `GameSystem.FileManager` | файловий менеджер (практична 12) |
| `GameSystem.Tests` | тести |

Опис архітектури та командного інтерфейсу: [docs/DESIGN.md](docs/DESIGN.md).

## Відповідність технічному завданню

| Вимога | Де виконано |
|---|---|
| Каталог: оновити й вивести список усіх персонажів | `catalog`, `catalog refresh`; у вікні вкладка «Каталог персонажів» |
| Каталог: загальна інформація й посилання на графіку | `catalog info <id>`, `sheet <ім'я>` |
| Каталог: створити персонажа через діалог, зберегти дані | `create char`, `save`, `continue` |
| Гра: вибір персонажів, початок, дії в циклі, збереження стану й результатів | `play`, `attack`/`heal`/`defend`/`ability`, `history`, `save`, `results` |
| Бізнес-логіка: парсинг JSON із API | `HttpGenshinApiClient` + DTO → `RemoteCharacterInfo`, `CharacterCatalog` |
| Бізнес-логіка гри: математика, покроковий режим, історія, стан, нові персонажі | розділ 9 дизайн-документа |
| Постійність: портрети в локальні файли (буфер) | `HttpPortraitProvider`, папка `portraits` |
| Постійність: save/load, продовження з останнього сейву | `save`, `load`, `continue` (розділ 10) |
| Графічний інтерфейс: картки каталогу, вікно-консоль із кнопками сейвів | `GameSystem.Gui` (розділи 11 і 13) |
| Розгортання | `scripts/publish.ps1`, `.github/workflows/release.yml` (розділ 12) |
