# Практична 12 — файловий менеджер у консолі

Це консольна програма, яка показує вміст папок, відкриває файли для читання і дає їх редагувати.
Зроблена на .NET 10 всередині мого проєкту GameSystem (окремий проєкт `GameSystem.FileManager`).
Все працює в одному процесі: не треба перезапускати програму, щоб перейти з папки у файл і назад.

## Як запустити

```
dotnet run --project GameSystem.FileManager
dotnet run --project GameSystem.FileManager -- C:\Temp
dotnet test
```

Другий варіант відкриває програму одразу у вказаній папці. Краще запускати у Windows Terminal.

## Як це працює

У програми три режими, як на схемі з завдання:

- **Directory** — список файлів і папок поточної директорії. Можна ходити по папках.
- **View** — перегляд файлу з номерами рядків, його можна гортати.
- **Edit** — редагування тексту з курсором.

Перемикання між режимами зроблено патерном State. Кожен режим це окремий клас
(`DirectoryMode`, `FileViewMode`, `EditMode`), а клас `FileManagerApp` тримає поточний режим
і міняє його, коли користувач відкриває файл, закриває його або переходить до редагування.
Одна й та сама клавіша в різних режимах робить різне: наприклад, Enter у Directory відкриває файл,
а в Edit розбиває рядок.

Помилки (немає доступу до папки, файл завеликий, не вдалося зберегти) не ламають програму:
вони ловляться і показуються червоним у рядку статусу внизу.

## Керування

| Режим | Клавіші |
|---|---|
| Directory | стрілки, PgUp/PgDn, Home/End — вибір; Enter — відкрити; Backspace — на рівень вгору; Esc або Q — вихід |
| View | стрілки, PgUp/PgDn, Home/End — прокрутка; E — редагувати; Q або Esc — закрити файл; M — для .md перемикає форматований і звичайний вигляд |
| Edit | стрілки, Home/End, Enter, Backspace, Delete, Tab; Ctrl+S (або F2) — зберегти; Esc — назад у перегляд |

Якщо в Edit є незбережені зміни, то перший Esc лише попереджає, а другий Esc відкидає зміни.

Ще є командний рядок: у Directory і View натискаєш `:` і вводиш команду.
Наприклад `:cd ..`, `:cd "My Documents"`, `:open notes.txt --edit`, `:goto 20`, `:help`, `:quit`.

## Що я взяв з попередніх практичних

Завдання радило використати вже написаний код, тому:

- **Парсер команд** (`CommandParser`, `CommandRegistry`, `RelayCommand` з GameSystem.CLI) — на ньому працює командний рядок `:`. Лапки і `--опції` розбирає той самий парсер.
- **`IDisplayer` і `DisplayKind`** — усі повідомлення у статус-рядку йдуть через них, а колір залежить від виду повідомлення (інфо, успіх, попередження, помилка).
- **Текстова система** (`Root`, `Heading`, `Paragraph`, `Link` і `ITextVisitor`) — файли `.md` відкриваються як форматований документ. Я написав новий візитор `StyledTextVisitor`, який малює те саме дерево кольоровими рядками з переносом слів. Самі класи вузлів не змінював.
- **`ConsoleDisplayer`** — для помилок при запуску і напису «Goodbye!».

## Як влаштований вивід

Робота з консоллю схована за інтерфейсом `ITerminal`, а робота з диском за `IFileSystem`.
Завдяки цьому в тестах можна підставити підроблений термінал і файлову систему в пам'яті
(`FakeTerminal`, `InMemoryFileSystem`), і тести не чіпають справжню консоль.

Екран малює клас `Canvas`: зверху заголовок, посередині тіло, внизу статус і підказки клавіш.
Кольори задаються ANSI-кодами, всі кольори зібрані в одному класі `Palette`.
Вміст файлів очищається від керівних символів, щоб файл не міг зламати екран.

## Структура

```
GameSystem.FileManager
  Modes/            режими (State)
  App/              FileManagerApp
  Rendering/        Canvas, стилі, кольори, візитор для тексту
  Editing/          TextBuffer (редагування), Viewport (прокрутка)
  Files/            IFileSystem
  Terminal/         ITerminal
  Infrastructure/   справжня консоль і диск
GameSystem.Tests/FileManager   тести
```

## Тести

Тести лежать у `GameSystem.Tests/FileManager`. Вони перевіряють режими і переходи між ними,
редагування тексту, збереження, командний рядок, прокрутку, форматований перегляд `.md`
та обробку помилок. Усього в проєкті 233 тести.
